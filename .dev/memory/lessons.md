# Lessons

Corrections and confirmed approaches. Detection cue: user says "no, X" / "don't Y" / "always Z".

## Swift 6 / SwiftPM (M1)
- Swift 6 strict concurrency: XCTest fake doubles that (a) conform to a `Sendable` protocol AND (b) hold mutable `var` state need `@unchecked Sendable` on the class, or the test won't compile. Also, a helper returning `private`/`fileprivate` fake types must itself be `fileprivate` (access-level leak error). Fix the TEST file, never loosen the production protocol's `Sendable`.
- Plan code blocks can be internally inconsistent — trust the TEST, not the impl snippet. In M1 two plan bugs surfaced: (1) HotkeySpec `description` modifier order rendered "⇧⌘2" not "⌘⇧2" (reorder to ⌃⌥⌘⇧); (2) SelectionGeometry `clamp` = `r.intersection(bounds)` gives height 100 but the plan's own test expects 110 → implement "snap origin to 0, clip far edge, preserve size". The failing test is the authoritative spec.
- `get { x }; nonmutating set { ... }` on ONE line is invalid Swift; accessors must be on separate lines.
- Every `MacShotCore` task's `swift test` compiles the WHOLE target, so parallel agents creating sibling files in one shared worktree race (a half-written sibling breaks everyone's compile). Serialize same-target waves; run TDD-artifact fail-checks in a throwaway `git worktree add --detach` overlaying only the HEAD test onto the parent.
- Reviewer hazard confirmed: an oro-task-reviewer ran `git checkout <sha>` in the SHARED exec worktree (T13 review) while the NEXT implementer (T14) was actively writing files there — it detached HEAD. It reattached cleanly and no work was lost, but this races the live sibling. ALWAYS give reviewers explicit `git worktree add --detach /tmp/...` instructions for parent-commit verification and forbid `git checkout` in the shared worktree. (This run's reviewer dispatches did instruct that; the T13 one still checked out — re-emphasize per dispatch.)
- Swift 6: `CaptureEngine` (and anything holding a `Preferences`) is NOT Sendable because `Preferences.store` is `KeyValueStore: AnyObject` (a class = non-Sendable). Storing such a value on a @MainActor type that crosses an async boundary needs `nonisolated(unsafe)` on the stored property (sole owner, main-actor access = bounded safe) — do NOT make KeyValueStore Sendable just to silence it (UserDefaults + InMemoryKVStore are reference types with mutable state). Revisit if M2+ shares the engine across actors.
