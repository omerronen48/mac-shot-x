# Lessons

Corrections and confirmed approaches. Detection cue: user says "no, X" / "don't Y" / "always Z".

## Swift 6 / SwiftPM (M1)
- Swift 6 strict concurrency: XCTest fake doubles that (a) conform to a `Sendable` protocol AND (b) hold mutable `var` state need `@unchecked Sendable` on the class, or the test won't compile. Also, a helper returning `private`/`fileprivate` fake types must itself be `fileprivate` (access-level leak error). Fix the TEST file, never loosen the production protocol's `Sendable`.
- Plan code blocks can be internally inconsistent — trust the TEST, not the impl snippet. In M1 two plan bugs surfaced: (1) HotkeySpec `description` modifier order rendered "⇧⌘2" not "⌘⇧2" (reorder to ⌃⌥⌘⇧); (2) SelectionGeometry `clamp` = `r.intersection(bounds)` gives height 100 but the plan's own test expects 110 → implement "snap origin to 0, clip far edge, preserve size". The failing test is the authoritative spec.
- `get { x }; nonmutating set { ... }` on ONE line is invalid Swift; accessors must be on separate lines.
- Every `MacShotCore` task's `swift test` compiles the WHOLE target, so parallel agents creating sibling files in one shared worktree race (a half-written sibling breaks everyone's compile). Serialize same-target waves; run TDD-artifact fail-checks in a throwaway `git worktree add --detach` overlaying only the HEAD test onto the parent.
- Reviewer hazard confirmed: an oro-task-reviewer ran `git checkout <sha>` in the SHARED exec worktree (T13 review) while the NEXT implementer (T14) was actively writing files there — it detached HEAD. It reattached cleanly and no work was lost, but this races the live sibling. ALWAYS give reviewers explicit `git worktree add --detach /tmp/...` instructions for parent-commit verification and forbid `git checkout` in the shared worktree. (This run's reviewer dispatches did instruct that; the T13 one still checked out — re-emphasize per dispatch.)
- Swift 6: `CaptureEngine` (and anything holding a `Preferences`) is NOT Sendable because `Preferences.store` is `KeyValueStore: AnyObject` (a class = non-Sendable). Storing such a value on a @MainActor type that crosses an async boundary needs `nonisolated(unsafe)` on the stored property (sole owner, main-actor access = bounded safe) — do NOT make KeyValueStore Sendable just to silence it (UserDefaults + InMemoryKVStore are reference types with mutable state). Revisit if M2+ shares the engine across actors.

## Swift 6 / SwiftPM (M2)
- Serialized same-target waves are still susceptible to a stale `.build` cache in the SHARED worktree: after T3 changed `CaptureResult`, a reviewer's first `swift test` for a DISJOINT sibling (OverlayStack) surfaced a phantom "CaptureResult has no member 'image'" from cached sibling test objects. A clean `swift build` then re-run cleared it. Reviewers who verify in the shared worktree should `swift build` first (or use the throwaway-worktree path) — don't trust the first incremental `swift test` after a sibling landed.
- A `Sendable` public struct requires every stored property Sendable: `OverlayStack`'s private nested `Panel` struct needed explicit `Sendable` conformance for the outer `OverlayStack: Sendable` to hold. Necessary, not over-build.
- macOS symlink trap: `NSTemporaryDirectory()` returns `/var/folders/…` but `FileManager.contentsOfDirectory` resolves to `/private/var/folders/…`. Path comparisons (e.g. pinned-set membership) fail silently. Fix: call `url.resolvingSymlinksInPath().path` on both sides before comparing. Apply at the data layer (HistoryStore), not in callers.
- macOS symlink trap (M2 T4): `NSTemporaryDirectory()` returns `/var/folders/...` but `FileManager.contentsOfDirectory` yields the resolved `/private/var/folders/...`. Comparing a stored path (from one) against an enumerated URL's `.path` (from the other) with raw string `==`/`Set.contains` silently always-misses. Fix at the data layer with `url.resolvingSymlinksInPath().path` on BOTH sides before comparing (HistoryStore does this for pin membership). Bites any "is this path in my persisted set" check on macOS temp dirs.
- `swift test` on this SwiftPM package prints a trailing "Test run with 0 tests in 0 suites" from the unused swift-testing runner — that is NOT a failure. The authoritative result is the XCTest line "Executed N tests, with 0 failures". Grep for `Executed .* tests` (or `Test Suite 'All tests' passed`), not the swift-testing summary, when asserting the gate.
- GUI-shell serialization (M2 W3): T5 QuickAccessPanel and T6 HistoryWindow are disjoint files but both compile into the MacShot exe target, so a parallel `swift build` mid-write races the same target — serialize same-exe-target GUI tasks exactly like same-lib-target core tasks. AppKit-over-SwiftUI was the ponytail-right call for the throwaway panel (4 buttons, no reactive binding); SwiftUI LazyVGrid was right for the history grid (list rendering + refresh).
